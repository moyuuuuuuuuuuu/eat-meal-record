# nutrition 扣子工作流（eat-meal-record 适配版）

## 兼容契约

- 保留开始节点入参：`text`、`image`、`audio`。
- 保留结束节点出参：`result`，其值仍是 JSON 数组字符串。
- 兼容 `FoodService::nutrition()` 的 `result` 读取和 `json_decode()`。
- 数组元素继续使用项目现有字段：`name`、`cat`、`is_common`、`is_ingredient`、`tags`、`units`、`nutrition`。

## 本次优化

1. 明确 `nutrition` 全部是每 100g 可食部数据，与 `food_nutrients` 表以及 `NutritionTemplate::calculate()` 的换算逻辑一致。
2. 图片分支不再把照片中当前一份的视觉估重写成全局 `food_units.weight`；无法确定稳定份量时仅返回“克 = 1g”。
3. 标签统一为“标签类型 => 标签数组”，类型与 `FoodTag` 枚举一致。
4. 三个模型节点温度由 `0.5` 降为 `0.2`，减少结构化输出漂移。
5. 末端代码节点增加 JSON 清洗与校验：
   - 去除 Markdown 代码块；
   - 兼容偶发的 `{ "foods": [...] }` 包装；
   - 校验 11 个必需营养字段及非负数值；
   - 校验单位枚举、正克重，并确保恰好一个默认单位；
   - 校验标签类型；
   - 丢弃不完整食物，最终仍输出项目需要的 JSON 数组字符串。
6. 标准化食品名称，减少 `FoodModel::updateOrCreate(['name' => ...])` 产生同物异名数据。

## 导入与配置

1. 在扣子中导入同目录生成的 ZIP 文件。
   ZIP 文件名带有 `optimized` 仅用于本地区分；包内工作流名保持为 `nutrition`，以满足 DSL 文件名必须以工作流名称开头的校验规则。
2. 检查导入后的语音识别插件授权和三个模型节点是否在当前空间可用。
3. 发布工作流后，将发布得到的工作流 ID 配置为项目环境变量 `COZE_NUTRITION_WORKFLOW_ID`。
4. 不要把工作流出参改成对象；当前 PHP 端要求 `result` 是 JSON 数组字符串。

## 建议验收样例

- 文字：`早餐吃了两个水煮鸡蛋和一碗小米粥`
- 图片：单一食物、多个菜品、只有餐具、模糊图片各一张
- 音频：包含数量、停顿词和食品同音字的普通话录音

验收重点：顶层为数组、每项有非空标签和单位、只有一个默认单位、营养字段完整、图片结果没有把当前照片视觉份量固化成全局单位重量。
